# Experiments X4 and X7

X4 asks whether the filters wardowl compiles from authorization engines' filter APIs agree with the
engines' own check APIs (the paper's section "Do Authorization Engines' Filters Agree With Their
Checks?", contribution C3). X7 measures how long a revoked permission keeps granting access end to
end, and what wardowl does when the authorizer or the store fails (threat model items (iii) and (v)).
The hypotheses, numeric rules and statistics were fixed first, in
[`PREREG_X4_X7.md`](PREREG_X4_X7.md), committed alone before any harness code.

| File | What it is |
|---|---|
| [`PREREG_X4_X7.md`](PREREG_X4_X7.md) | The pre-registration: design, hypotheses, confirm and falsify rules, statistics |
| [`x4_engines.py`](x4_engines.py) | X4 driver: parts a (one revision), b (unpinned, under a writer), c (truncation at scale, with X4d's latency) |
| [`x7_revocation_faults.py`](x7_revocation_faults.py) | X7 driver: `revocation` (X7a) and `faults` (X7b) |
| [`x4_stats.py`](x4_stats.py), [`x7_stats.py`](x7_stats.py) | The pre-registered verdicts, CSV tables and a markdown report |
| [`x4x7_world.py`](x4x7_world.py) | The seeded world (tenants, users, nested groups, folders, documents), each engine's encoding of it, and the oracle |
| [`x4x7_common.py`](x4x7_common.py) | Records, versions, annotations, admin clients for the engines, Docker control, the bootstrap |
| [`x4x7_proxy.py`](x4x7_proxy.py) | The fault-injection proxy (HTTP and TCP; standard library only) |
| [`x4x7_policies/`](x4x7_policies) | The OPA (Rego) and Cerbos policies; OpenFGA's model and SpiceDB's schema are in `x4x7_world.py` |
| [`../../.github/workflows/paper-x4-x7.yml`](../../.github/workflows/paper-x4-x7.yml) | Starts the servers and runs everything in GitHub Actions |

## Running

Everything runs in GitHub Actions; nothing is meant to run on a laptop. A push to `paper/x4-x7` runs
the profile the workflow's `PROFILE` names; Actions > paper-x4-x7 > Run workflow chooses one:

- `smoke`: one seed, small worlds, short fault phases. It exists to find faults in the harness, and
  its numbers are never analysed.
- `full`: the pre-registered design (5 seeds and the sizes of `PREREG_X4_X7.md`).

Fourteen jobs run in parallel, one per engine and part:

| Job | What | Servers |
|---|---|---|
| `x4-openfga`, `x4-spicedb` | X4a and X4b | OpenFGA or SpiceDB on Postgres |
| `x4-policy` | X4a, X4b and X4c for OPA, X4a for Cerbos, the controls | OPA (process), Cerbos |
| `x4-openfga-scale`, `x4-spicedb-scale` | X4c and X4d at 100,000 documents | OpenFGA or SpiceDB on Postgres |
| `x7a-openfga` | revocation: `openfga`, `openfga-cached-hc`, `openfga-cached-ml` | two OpenFGA servers on one Postgres (the second with the check-query cache), Redis |
| `x7a-spicedb` | revocation: `spicedb-fc`, `spicedb-ml` | SpiceDB on Postgres, Redis |
| `x7a-policy` | revocation: `opa-data`, `opa-policy`, `cerbos-policy` | OPA, Cerbos watching a policy directory, Redis |
| `x7a-acl` | revocation: `acl-pgvector`, `acl-qdrant` | pgvector, Qdrant, Redis |
| `x7b-openfga`, `x7b-spicedb`, `x7b-opa`, `x7b-cerbos` | faults on each engine | the engine, the proxy |
| `x7b-stores` | faults on pgvector and Qdrant | pgvector, Qdrant, the proxy |

Images and versions are the conformance campaign's: OpenFGA v1.22.0, SpiceDB v1.56.2, Cerbos 0.56.0,
OPA 1.21.2, `pgvector/pgvector:pg17`, Qdrant v1.19.2, Redis 8.10.2. OpenFGA and SpiceDB use a Postgres
datastore (the campaign used memory), so that a restarted engine keeps its data.

### Amendment 2: the targeted rerun

The workflow's `configuration` (input, or `CONFIGURATION` for a push) is `full` for the fourteen jobs
above or `amendment2` for the targeted rerun of amendment 2, which installs wardowl from
`fix/revocation-faults` at `WARDOWL_REF` instead of this branch's copy and runs five jobs:

| Job | What | Servers |
|---|---|---|
| `a2-x7a-spicedb` | revocation: `spicedb-ml`, every cache condition | SpiceDB on Postgres, Redis |
| `a2-x7a-cerbos` | revocation: `cerbos-policy` without a cache and with `invalidate()` (`source_staleness=10`) | Cerbos watching a policy directory, Redis |
| `a2-x7b-spicedb` | faults: `empty`, and `empty-lookup` (only LookupResources answers emptied) | SpiceDB, the proxy |
| `a2-x7b-pgvector` | faults: `down`, `refuse`, `blackhole` and `lock` (a table lock), the last two also with `statement_timeout`, retrievals started every 0.2 s | pgvector, the proxy |
| `a2-x7b-qdrant` | faults: `down`, `refuse`, `blackhole`, `http500`, `http503`, `truncate`, retrievals started every 0.2 s | Qdrant, the proxy |

`x7_stats.py` sees amendment 2's records and judges A2-H1 to A2-H8 only, beside the full run's
numbers for the same cells; the registered rules' tables are shown without verdicts.

## Reading the results

The report job publishes every run to the branch `results/x4-x7`, under `<run id>-<run attempt>/`:

| Path | Content |
|---|---|
| `RUN.md` | Commit, profile, run URL, which jobs produced artifacts, the jobs' results |
| `x4_report.md`, `x7_report.md` | The verdicts first, then the tables and the harness's errors |
| `*.csv` | The tables of the reports |
| `x4_stats.log`, `x7_stats.log` | Every verdict as printed |
| `logs/<job>.log` | The last 200 lines of each job's driver log; `logs/<job>--<server>.log` the servers' last lines |
| `jobs/` | Each job's exit status and its own report |
| `raw/<job>--<file>.jsonl.gz` | Every record (left out if larger than 60 MB; the artifacts keep them for 90 days) |

```
git fetch origin results/x4-x7
git show origin/results/x4-x7:<run id>-1/x4_report.md
```

Each record is one JSON object with a `type`: `run-start` and `versions` (configuration, commit,
packages, image digests); `x4a-subject` (one user of one profile: the filter's status and size, the
counts of false admits and false denials against the check and against the oracle, the reproduced
ones, examples, timings); `x4b-trial` (one user under one condition: disagreements, the write window
and how many disagreements it explains); `x4c-engine-call`, `x4c-filter`, `x4c-query` (raw list calls,
wardowl's filter, one retrieval with its recall); `x4d-latency`; `x7a-trial` (one revocation: time to
effect, the bound, polls and flaps); `x7b-episode` (one fault episode: outcomes inside the fault,
leaks, error classes and messages, recovery, and every request's start, duration and outcome);
`harness-error` (an error the harness met, counted).

## Design decisions

- **The oracle is independent of wardowl's filter code** (`x4x7_world.Model`), and every profile is
  compared with it: a filter-and-check disagreement is attributed to translation only when the check
  agrees with the oracle (guard G2) and the controls behave (G1).
- **One revision.** SpiceDB pins both calls with `atExactSnapshot` at the token of the last write;
  OpenFGA has no snapshot token in its API, so its X4a world is quiescent and read with
  `HIGHER_CONSISTENCY`; OPA and Cerbos are stateless per request.
- **OPA has two filter routes.** wardowl's own (a filter document written beside the decision rule)
  and OPA's Compile API with the UCAST target, translated by the harness (`eq` and `in` only); a
  residual with anything else gives no filter. Bans exist only in the exclusion profiles, because the
  filter language has no negation.
- **Streaming ListObjects** is measured at the engine level only: wardowl does not use it.
- **ttl 0** means no `CachingAuthorizer`, which requires a positive ttl.
- **Faults are injected by a proxy of our own** (not toxiproxy), because two of the faults rewrite
  answers; `down` kills the server itself.
